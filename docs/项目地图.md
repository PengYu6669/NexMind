## 面试表达开场

> NexMind 是一个以个人知识库为事实来源、以混合 RAG 提供上下文、以 LangGraph 编排学习任务的全栈知识系统。用户保存笔记后，系统异步索引内容；学习任务由 PostgreSQL 队列原子领取，经检索、决策、可选联网审计、计划、执行和教练节点生成学习卡片，再通过 SM-2 进入复习闭环。我的重点不是把它描述成通用 Agent 平台，而是保证学习链路可追踪、可恢复、可降级。

| # | 问题 | 结构化参考答案 | 深挖准备/证据 |
| --- | --- | --- | --- |
| 1 | 这个项目解决什么问题？ | 笔记工具擅长存储但难以找回和持续学习；项目把捕获、混合检索、Agent 学习任务、卡片和间隔复习串成闭环。当前定位是学习工作流，不夸大为通用自动化平台。 | [README](../README.md)、说清目标用户、未实现边界。 |
| 2 | 整体架构怎么分层？ | Next.js 页面/API 是交互边界，`lib` 是领域与编排，PostgreSQL/Prisma 是事实状态，pgvector 是检索索引，外部模型/MCP 是可降级依赖。请求链和异步任务链通过数据库连接。 | [CLAUDE](../CLAUDE.md)、[schema](../prisma/schema.prisma)。 |
| 3 | 从保存笔记到可以搜索的链路？ | `NoteEditor -> PUT /api/notes/[id] -> Note`，响应生命周期内用 `after()` 调用 `indexNoteForRag`，先删除该用户该笔记旧 chunk，再清洗、分块、Embedding，并写向量和 `search_vector`。 | [笔记 API](../app/api/notes/%5Bid%5D/route.ts#L74)、[索引](../lib/rag.ts#L594)。追问一致性失败怎么办。 |
| 4 | 为什么使用混合检索？ | 向量检索擅长语义近似但可能漏掉专有名词；FTS/trigram 擅长精确词项但不理解同义表达。系统并行利用距离与词项排名，再去重排序，提高不同查询类型的鲁棒性。 | [查询 SQL](../lib/rag.ts#L739)、准备纯向量替代方案及评估集。 |
| 5 | RAG 如何分块？ | `buildStructuredChunks` 先识别文档类型和结构，再采用不同 chunk size/overlap；overlap 保留跨边界语义，但会增加存储、Embedding 成本和重复召回，因此必须用测试与召回集调参。 | [分块](../lib/rag-chunking.ts#L59)、[测试](../tests/rag-chunking.test.ts)。 |
| 6 | 为什么向量维度固定为 1024？ | 数据库 `vector(n)`、模型输出和 HNSW 索引必须一致；项目将 1024 作为当前迁移契约并在写入前校验。换模型不能只改环境变量，需要重建列/索引并重新 Embedding。 | [schema 校验](../lib/rag.ts#L453)、[迁移](../prisma/migrations/20260715100000_finalize_rag_schema/migration.sql)。 |
| 7 | 如何防止跨用户 RAG 泄露？ | 索引行保存 `user_id`，索引删除、向量查询和全文查询均按 `userId` 限制；API 的身份来自服务端 JWT，而不是相信请求体传入的用户 ID。 | [ragSearch](../lib/rag.ts#L852)、[搜索 API](../app/api/search/route.ts)。 |
| 8 | 如何评估 RAG 效果？ | 建立带期望来源的查询集，分别统计 Recall@K、MRR、无关片段率与回答引用正确率；对 chunk、topK、混合权重做离线对比，再记录延迟和 Embedding 成本。当前仓库主要覆盖结构和策略测试，完整检索评测集仍待建设。 | 必须诚实说明“待建设”，不能伪造线上指标。 |
| 9 | 为什么使用 LangGraph？ | 任务不是单次问答，而是带分支、工具、持久状态、人工输入和恢复的长流程；LangGraph 把节点、条件边和 checkpoint 显式化，比在一个函数里堆 if/else 更易追踪与恢复，但增加了状态设计复杂度。 | [图构建](../lib/nextclaw-langgraph.ts#L353)。对比普通 chain/队列状态机。 |
| 10 | LangGraph State 怎么设计？ | State 包含身份与任务不变量、笔记/RAG 上下文、计划、工具结果、metrics、steps 和 HITL 信息；跨节点数据必须可序列化，不能放连接、函数或类实例，否则 checkpoint 和 UI 无法可靠恢复。 | [State 类型](../lib/nextclaw-agent-types.ts)。 |
| 11 | 节点按什么边界拆？ | 按“单一决策或副作用”拆：加载事实、监督决策、搜索/抓取/审计、计划、执行、教练生成、持久化和收口。节点负责执行，条件边只负责路由，持久化节点集中写业务产物。 | [节点](../lib/nextclaw-langgraph.ts#L423)、[边](../lib/nextclaw-langgraph.ts#L1598)。 |
| 12 | Supervisor、Planner、Executor、Coach 区别？ | Supervisor 决定是否需要外部信息及路线；Planner 将目标变成结构化步骤；Executor 按计划调用工具；Coach 将证据与执行结果转为学习内容。拆分避免一个提示词同时决策、执行和写作导致难测。 | [supervisor](../lib/nextclaw-langgraph.ts#L518)、[planner](../lib/nextclaw-langgraph.ts#L1077)。 |
| 13 | 为什么条件边抽成纯函数？ | 路由只依赖 State，不应访问数据库或模型；抽离后可用固定输入覆盖每个分支，减少修改大图时的回归风险，也让节点副作用和控制流分离。 | [routing](../lib/nextclaw-routing.ts)、[测试](../tests/nextclaw-routing.test.ts)。 |
| 14 | 外部搜索失败怎么办？ | 可选搜索/抓取/审计按策略记录 metrics 和 steps，并在证据仍足够时降级继续；如果缺少必要来源且无法可靠执行，则进入 `WAITING_INPUT`，要求用户提供 URL，而不是错误标成取消。 | [HITL 节点](../lib/nextclaw-langgraph.ts#L695)、[状态 UI](../lib/nextclaw-task-ui.ts#L58)。 |
| 15 | checkpoint 如何恢复？ | `jobId` 作为 thread ID；运行前读取最近 checkpoint，补回受信任的 `userId/noteId/jobType`，再继续 invoke。恢复输入也要校验 URL，防止脏 checkpoint 或用户输入改变任务所有权。 | [运行入口](../lib/nextclaw-langgraph.ts#L1659)、[恢复 API](../app/api/nextclaw/tasks/%5BjobId%5D/route.ts)。 |
| 16 | 为什么 LangGraph 外还需要 LearningJob？ | checkpoint 管图内状态，LearningJob 管业务生命周期、调度、并发领取、重试、UI 查询与审计；两者职责不同。没有 Job 表，Web 请求结束后难以可靠表达待执行、失败和人工等待。 | [LearningJob](../prisma/schema.prisma)、[runner](../lib/learning-jobs-runner.ts)。 |
| 17 | `FOR UPDATE SKIP LOCKED` 有什么作用？ | Worker 在事务中锁住候选任务并跳过已被其他 Worker 锁定的行，可并发领取而不重复 claim。它不自动保证节点副作用幂等，持久化仍需唯一约束或去重策略。 | [claim SQL](../lib/learning-jobs-runner.ts#L26)。 |
| 18 | Worker 执行中宕机怎么办？ | Job 保存 `RUNNING/startedAt/attempts/lastError`，runner 有租约和重试策略，可将超时任务重新纳入领取；图 checkpoint 可减少完全重跑。但外部调用和写入仍要按幂等边界审视。 | [runner](../lib/learning-jobs-runner.ts)、[策略](../lib/nextclaw-workflow-policy.ts)。 |
| 19 | 如何避免重复学习卡片？ | 任务携带笔记版本 `noteUpdatedAt` 用于跳过过期任务，持久化集中在 persist 节点，并按现有卡片/来源语义处理。严格 exactly-once 不能只靠队列，需要数据库唯一键或幂等键；这是可继续加强点。 | [schema](../prisma/schema.prisma)、[persist](../lib/nextclaw-langgraph.ts#L1428)。 |
| 20 | 学习闭环怎么完成？ | persist 写 `LearningCard`，并为笔记 upsert `ReviewItem`；用户在 `/learn` 作答后，评分 API 更新掌握分、间隔、easeFactor 和下次到期时间，实现生成到复习的闭环。 | [persist](../lib/nextclaw-langgraph.ts#L1428)、[评分](../app/api/nextclaw/review/score/route.ts)。 |
| 21 | 为什么用 SSE？ | 任务状态与 AI 文本主要是服务端单向推送，SSE 基于 HTTP、浏览器支持好、实现和重连成本低；若未来需要高频双向协作再考虑 WebSocket。当前 SSE 断线会重连并从数据库状态重新同步。 | [feed stream](../app/api/nextclaw/feed/stream/route.ts#L99)、[客户端](../components/nextclaw/NextClawPageClient.tsx)。 |
| 22 | 身份认证和授权怎么做？ | 登录校验 bcrypt 密码后签发 HttpOnly JWT；API 用 `getAuthUser()` 解析身份。认证只说明“你是谁”，授权还要求每个用户资源查询都附带 `userId`，避免 IDOR。 | [auth](../lib/auth.ts)、[登录](../app/api/auth/login/route.ts)。 |
| 23 | 项目做了哪些输入安全？ | Zod 约束 JSON 契约，限流抑制滥用，URL 在存储/抓取前执行协议、DNS 与私网检查防 SSRF，内部 Cron 使用独立 Bearer token；系统密钥只从环境读取。 | [inputs](../lib/api-inputs.ts)、[SSRF](../lib/safe-public-url.ts)、[Cron](../lib/internal-cron.ts)。 |
| 24 | Prisma 与 RAG 原始 SQL 为什么并存？ | 普通业务关系由 Prisma 提供类型和迁移；向量列、HNSW、GIN、FTS 排名需要 PostgreSQL 特性与精细 SQL，因此 RAG 使用审核过的迁移和参数化查询。代价是类型保障较弱、迁移责任更高。 | [schema](../prisma/schema.prisma)、[rag](../lib/rag.ts)。 |
| 25 | migration 和 db push 有何区别？ | migration 是可审查、可复现、适合团队和生产的历史；`db push` 直接对齐 schema，适合短期原型但缺少可部署历史。项目生产使用 `prisma migrate deploy`，构建不能修改数据库。 | [package scripts](../package.json)、[AGENTS](../AGENTS.md)。 |
| 26 | 测试策略是什么？ | 纯路由、计划归一化、分块、限流和 URL 安全用 Vitest；`test:core` 连接真实 PostgreSQL 验证迁移、RAG schema、任务生命周期和鉴权；lint/typecheck/build 作为交付门禁。 | [tests](../tests)、[core chain](../scripts/test-core-chain.ts)。 |
| 27 | 数据库或 RAG 不可用如何发现？ | `/api/health/live` 只验证进程存活，`ready` 验证数据库和 RAG schema；部署平台应只把 readiness 通过的实例接入流量，日志再结合任务 `lastError/steps` 定位。 | [ready](../app/api/health/ready/route.ts)、[live](../app/api/health/live/route.ts)。 |
| 28 | 扩大 100 倍后先优化哪里？ | 先测而非猜：重点观察 Embedding/LLM 延迟与成本、任务领取吞吐、SSE 连接、向量查询和大表索引。可拆独立 Worker、批量 Embedding、连接池、队列指标和分区；不能声称当前已经验证高并发。 | 给出指标：P95、队列深度、失败率、token 成本、DB CPU。 |
| 29 | 当前最大的技术债是什么？ | `nextclaw-langgraph.ts`、`rag.ts`、编辑器和聊天面板偏大；异步调度仍与 Web 进程关系较近，RAG 缺少标准评测集，幂等约束还能增强。优先抽纯策略和建立评测，不做无关目录重构。 | [CLAUDE 大模块](../CLAUDE.md)。 |
| 30 | 如果面试官问“这些是不是 AI 写的”？ | 如实说明 AI 参与了实现，但自己通过调用链梳理、测试、故障复现和独立改动取得所有权；随后用一个亲手完成的 Bug、设计取舍和验证结果证明能力。不能把没理解的生成代码冒充个人设计。 | 完成 TodoList 的三个动手改动后再形成个人案例。 |

## 毕业标准

- 不看文档，15 分钟画出架构、两条数据流和 LangGraph DAG。
- 随机抽取上面任意 10 题，每题 2 分钟结构化回答，并承受“为什么/替代方案/失败场景/如何验证”四轮追问。
- 独立完成一个 LangGraph 路由改动、一个 RAG 调参实验和一个故障修复，均带测试与提交记录。
- 从空环境部署成功，能用 health、日志、数据库状态和任务 steps 定位一次故障。
- 能明确区分“代码已确认”“个人取舍”“当前限制”，不编造用户量、性能和线上指标。
